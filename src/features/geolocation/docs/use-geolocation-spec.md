# useGeolocation 規格

React hook 僅訂閱狀態；取樣排程與瀏覽器 API 生命週期由 geolocation service 管理。

## 取樣排程

- 不使用持續的 `watchPosition()`。
- 每分鐘分成六個固定 10 秒視窗：`00.000–10.000`、`10.001–20.000`，依此類推至 `50.001–59.999`。
- 每個視窗以 window key 節流，最多呼叫一次 `getCurrentPosition()`。
- 相鄰兩次實際請求至少間隔 10 秒；若 App 在視窗尾端啟動，不會跨界立即重複請求。
- 前一次請求仍在執行時略過新視窗，不建立併發定位請求。
- 高精度定位、`maximumAge: 0`、timeout 8 秒。

## 最近樣本

- 成功位置連同實際取樣時間 `sampledAtMs` 保存在記憶體，最多有效 20 秒。
- 20 秒由 10 秒取樣週期、8 秒請求 timeout 與 2 秒排程誤差組成，不是任意快取時間。
- 計數或儲存時，`getFreshGpsSnapshot()` 提供最近一次成功定位；若定位已超過 20 秒則回傳 `null`。
- 單次取樣失敗時，仍可使用尚未過期的上一筆位置。
- 超過 20 秒沒有成功樣本時，清除位置並顯示「GPS 最近樣本已逾時」。
- 清除的只有尚未寫入事件的記憶體定位資料；計數、Save 事件及先前已保存的 GPS 資料不受影響。

## 權限與生命週期

- 啟動前先查詢 Permissions API；已拒絕時不呼叫定位 API。
- 監聽權限變更，重新允許後從當前取樣窗恢復。
- 分頁進入背景時清除排程 timer；回到前景只處理當前視窗，不補跑過去視窗。
- React Strict Mode 清理後，舊的非同步 callback 不得更新 state。
